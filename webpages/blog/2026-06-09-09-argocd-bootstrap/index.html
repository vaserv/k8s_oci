Step 9: bootstrapping ArgoCD

The next rollout path is GitOps. ArgoCD sits in its own namespace, gets an HTTPS ingress, and then owns the child Applications that manage the existing workloads.

Bootstrap command 
kubectl apply -k manifests/argocd/bootstrap
kubectl -n default get pods
kubectl -n default get applications
What changed
  • ArgoCD is installed from the upstream manifest.
  • The server runs behind TLS at a dedicated hostname.
  • The control plane runs in the `default` namespace in this cluster layout.
  • A bootstrap Application fans out into smaller workload Applications.
  • The child apps now include `shared-infra`, `webpages`, `oci-test`, and `jellyfin`.
Security notes

Do not expose the admin credentials in the repo. Read the bootstrap password once, rotate it, and keep the project destination scope tight.
